# ESP32-S3 蓝牙串口桥接示例

这个工程运行在另一块 ESP32-S3 上，将遥控器的 BLE 数据转发给实体 UART 设备。它负责桥接，不直接驱动电机。不要将本示例烧录到遥控器 COM11。

## 接线与构建

默认 UART1：RX 为 GPIO18，TX 为 GPIO17，115200 波特率、8N1。与目标设备交叉连接 TX/RX，并连接共同地线，使用 3.3V 电平。更改接线时同步修改源码引脚。

在本目录执行 `python -m platformio run` 编译；烧录使用 `python -m platformio run -t upload --upload-port 实际接收板端口`。使用已安装 PlatformIO 的 Python 环境。

## 数据流

遥控器 → NUS 写入特征 → UART1；目标 UART1 → NUS 通知 → 遥控器回显。USB CDC 也输出收到的无线数据。桥接不解析控制协议，目标必须按[协议说明](../../docs/CONTROL_PROTOCOL.md)解码；可使用[UART 接收示例](../Serial-Control-Receiver/README.md)。

二进制帧固定 20 字节，JSON、HEX 和文本按换行拼接。BLE 通知或 UART 单次读取不是完整帧的边界。低波特率建议使用二进制并降低发送频率。

## 远端串口参数

扩展特征 `6e400004-b5a3-f393-e0a9-e50e24dcca9e` 接收 4 字节小端波特率，支持 9600、19200、38400、57600、115200。程序更新实体 UART 后发布实际波特率，并保存到 NVS；遥控器读取该特征核对结果。普通蓝牙模块不一定支持此扩展。

## 失联与验证边界

队列溢出累计内部 `dropped` 计数。无线写入成功只表示数据进入传输流程。连续 5000ms 未收到无线数据时，桥接清空队列并发送归零帧；此计时针对收到的数据块，不代表 CRC 有效控制帧。

真正的控制目标应独立检查完整帧、CRC、序号和超时。UART 接收示例使用 300ms 有效帧超时，并要求按住 A 才产生电机控制意图。本工程的构建验证不等于外接执行器验证。完整步骤见[接收端接入教程](../../docs/RECEIVER_INTEGRATION.md)。
