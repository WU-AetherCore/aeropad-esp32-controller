# 控制数据协议 v1

本协议是本派生工程新增协议，不保证兼容原作者接收端。实际编码以 `src/ControlPacket.h` 为准；本地测试为 `tools/test_control_packet.cpp`。

## 四种发送格式

蓝牙中心 → 发送设置：上下选择格式/间隔，左右改变，X返回。设置立即写入NVS，旧版JSON开关自动迁移为格式0或1。

|编号/名称|线上内容|单帧长度（含换行，不含C字符串末尾NUL）|建议接收方式|
|---|---|---|---|
|0 二进制|20个原始字节|固定20字节|串口助手勾选HEX接收，程序按同步头+CRC解析|
|1 JSON文本|UTF-8兼容ASCII JSON对象，以LF结束|96～127字节，随数字位数变化|文本接收，按换行拼接后解析JSON|
|2 HEX十六进制|二进制帧的20个字节转为大写ASCII HEX，空格分隔，以LF结束|固定60字节：40个HEX字符+19个空格+1个LF|文本接收看到`A5 5A ...`；HEX接收会显示这些ASCII字符的编码|
|3 文本数据|`AP1`开头的带字段名ASCII，以LF结束|64～90字节，随数字位数变化|文本接收，按换行分帧，再拆`key=value`|

HEX是“字节值的文本表示”，与原始二进制是不同的线上格式。文本与JSON不含CRC；需CRC时使用二进制或HEX。编码缓冲区192字节，错误/容量不足返回0，不发送半个逻辑帧。

## 模拟量与状态字段

|JSON字段|文本字段|含义|类型/范围|
|---|---|---|---|
|v|`AP1`中的1|协议版本|整数1|
|seq|seq|帧序号，含释放帧，每发送一帧加1，255后回0|uint8，0～255|
|lx、ly|LX、LY|左摇杆水平/垂直输出|有符号整数，-100～100，校准中心/死区内为0|
|rx、ry|RX、RY|右摇杆水平/垂直输出|同上|
|kl、kr|KL、KR|左、右两个ADC旋钮的归一化输出|同上；不是0～4095原始ADC|
|buttons|BTN|18路按键/拨杆位图|uint32有效低18位；JSON十进制，文本固定5位大写HEX|
|ax、ay|AX、AY|MPU6050的X/Y倾角归一化控制量|有符号-100～100；±45°映射±100，超过截断；不是角度单位，也不是立方体三轴显示值|
|neutral|N|释放/停止标志|0正常；1时所有轴、旋钮、按键及AX/AY清零|

轴方向取当前引脚及校准映射，不在协议层猜测无人机/车辆油门正负。接收端应自行定义油门、转向、俯仰等用途。原始按键电平低表示按下，协议已转换为 **bit=1表示按下/拨杆有效**。

## 二进制布局：20字节

多字节字段小端；六轴和AX/AY是int8的二进制补码，例如-100=0x9C、100=0x64。接收时用int8_t解释，不能当uint8_t显示为156。

|偏移|字节数|类型|内容|
|---|---|---|---|
|0|1|uint8|同步头A5|
|1|1|uint8|同步头5A|
|2|1|uint8|版本01|
|3|1|uint8|帧类型01（控制）|
|4|1|uint8|seq|
|5、6|各1|int8|LX、LY|
|7、8|各1|int8|RX、RY|
|9、10|各1|int8|KL、KR|
|11～13|3|uint24 LE|按键位图，bit18～23保留0|
|14、15|各1|int8|AX、AY|
|16|1|uint8|bit0=neutral，其他位保留0|
|17|1|uint8|保留0|
|18～19|2|uint16 LE|CRC，低字节在18，高字节在19|

CRC16-CCITT-FALSE：多项式0x1021，初始0xFFFF，RefIn/RefOut=false，XorOut=0；仅覆盖偏移0～17这18字节。标准向量ASCII `123456789`的CRC=0x29B1。

## BLE分片与UART

正常静止帧的JSON与文本例子（序号0，所有按键松开）：

```json
{"v":1,"seq":0,"lx":0,"ly":0,"rx":0,"ry":0,"kl":0,"kr":0,"buttons":0,"ax":0,"ay":0,"neutral":0}
```

```text
AP1 seq=0 LX=0 LY=0 RX=0 RY=0 KL=0 KR=0 BTN=00000 AX=0 AY=0 N=0
```

线上每行末尾均含一个`0A`（LF）。若左摇杆X=50、右摇杆Y=-20且按A，分别变为`lx:50`/`LX=50`、`ry:-20`/`RY=-20`、`buttons:1`/`BTN=00001`。接收程序不能把BTN的HEX字符串直接当十进制。

支持NUS服务`6e400001-b5a3-f393-e0a9-e50e24dcca9e`（写0002/通知0003）和FFE0/FFE1。默认MTU23时每次写最多20字节，其他MTU最多180字节。**一次GATT写入不等于一帧**。接收端按20字节+CRC复原二进制，ASCII格式按LF复原；忽略空行，限制行长，断线时清除半帧。

发送间隔可选20、50、100、200、250、500、1000、1500、2000ms，分别约50、20、10、5、4、2、1、0.67、0.5帧/秒。它是调度间隔，不保证无线拥塞时严格频率。退出控制/断开时尝试发送neutral，接收端仍需独立失联处理。

8N1串口每字节约10bit。例如最长JSON127字节在20ms发送约6350字节/秒，115200bps通常有带宽空间，9600bps的约960字节/秒则不够；应提高UART速度、增加间隔或改二进制。2秒间隔适合慢速状态传输，不适合需要快速响应的运动控制。

独立接收端示例的失联超时为5000ms，以容纳2000ms设置。对实际执行器应根据用途配置自己的最大间隔和失联动作，不能把无线写成功当作设备动作成功。

## 串口设置及回显

串口设置位于蓝牙模块控制内：未连接页面按B打开模块设置，选择串口设置按O；连接后设备操作菜单选择串口设置。进入后上下选择本机/对方，本机左右切换关闭、原始二进制、HEX、文本、JSON五种回显选项，对方按O进入远程参数页，X逐级返回。

原始二进制直接输出收到的通知字节，不加前缀或换行；HEX把同一批字节转为可读十六进制。例如收到ASCII `AT`：原始模式输出字节`41 54`，HEX显示字符`41 54`，文本预览显示`AT`。发送格式和接收回显格式是独立设置，不会把远端发来的任意数据自动转换成控制协议帧。

COM11是本机USB CDC，回显关闭、HEX、文本转义、JSON是显示格式，不是假UART波特率。本机接收通知排入512字节缓冲并在UI主循环输出，溢出明确报告丢弃字节；文本模式将非ASCII字节转成`\xNN`，JSON模式输出`len`、连续大写`hex`和转义后的`text`字段。USB回显不等于对方UART参数已正确。

远程波特率需要对方提供NUS扩展特征`6e400004-b5a3-f393-e0a9-e50e24dcca9e`：Read/Write，4字节小端实际波特率。支持9600/19200/38400/57600/115200，写后读回相同才显示已生效。WUFUDONG实际提供FFE0，未提供此扩展，因此当前显示不支持远程设置；设备名称不能确定芯片型号或AT配置命令，不盲发AT指令。

## 蓝牙HID与本协议的区别

“蓝牙游戏手柄”发送标准HID（6个16位轴、14按钮和方向帽），不使用本协议的20字节帧，也不受模块发送格式/间隔设置影响。本协议专用于“蓝牙模块控制”。TX表示完整逻辑帧已提交BLE写入，RX表示通知字节数，ERR表示BLE写入失败；都不是外部设备执行确认。
