# 无人机、四驱车：遥控、设置和默认预设

## 操作规则

遥控页与设置页的操作分开，页脚只显示当前页面可用的按键。

|界面|O|A|B|X|
|---|---|---|---|---|
|标准 NRC1 遥控/回传|长按1秒请求启用，需在线回传、回中及低油门|立即停止；保持A时禁止重新启用|长按700ms切换显示；运行中只能切换遥控/回传，不改变发送状态|单键无动作；B+X同时保持350ms停止并退出|
|自定义协议遥控|开始/停止发送|立即停止发送|长按700ms进入设置；发送中拒绝进入设置，发送继续|单键无动作；B+X同时保持350ms停止并退出|
|设置菜单|确认选中的项目|打开保存预设|无动作|返回遥控，保持停止|
|参数、内容、映射页|应用当前配置为默认并回到遥控|打开保存预设|同组下一页|返回设置菜单，不应用草稿|
|我的预设|执行保存/应用/删除|无设置动作|无动作|返回设置菜单|
|默认控制模式|确认标准 NRC1 或当前自定义协议|无设置动作|无动作|返回设置菜单|

设置页上下键/左摇杆上下选择，左右键/左摇杆左右修改；摇杆在遥控页始终作为控制数据，不会修改菜单或回显格式。设置页显示单键X返回，B+X提示只出现在遥控/回传页。

标准 NRC1 运行时不能进入或修改设置。停止请求后，如果最近的接收端回传仍显示启用状态，继续发送停止帧并等待停止确认；陈旧回传不会作为已停止的证明。自定义协议不具有通用远端启用/停止反馈语义，发送停止不等于飞控或电机已经停止；对端必须自行实现停止和失联保护。

## 找到并使用预设

1. 停止控制后长按 B，进入设置菜单。
2. 选择「保存 / 管理预设」，按 O。列表同时显示预设1～5，已保存项绿色、选中项青色、空项白色。
3. 上下选槽位，左右选「应用为默认预设」，按 O。
4. 应用成功自动回到遥控页，顶部显示「默认 · 预设N」，此时发送保持停止，按 O 手动开始。

下一次进入同一个车型或开机重启后，自动恢复这个预设的完整射频参数、地址、包长度、间隔、数据来源、常量、映射和摇杆方向，并打开对应的自定义遥控页。不会自动开始发送。

无人机与四驱车的五个槽位及默认选择分别保存，互不覆盖。旧版保存的数据仍可加载；旧版本没有摇杆方向字段时补充车型默认方向，原射频参数和字节内容不改。

## 草稿、保存槽位与应用默认

这三件事分别存储：

- **编辑草稿**：停止后的参数修改约800ms自动保存，退出也保存。只是保存草稿，不替换默认协议。
- **保存引导**：在射频、通信、地址、发送内容、映射或摇杆方向设置页，按 A 直接打开保存列表。上下选择预设1～5，按 O 保存；成功显示具体槽位，自动选中「应用为默认预设」，再按 O 才应用。左右仍可切换保存、应用、删除。保存会覆盖选中的已有槽位。
- **保存槽位**：在「保存 / 管理预设」选保存，O写入指定槽位；已有槽位会被覆盖。保存槽位不会自动开始发送，也不会自动改变默认选择。
- **应用默认**：选择一个槽位并应用，或在参数页按O应用当前配置。完整配置和模式选择作为一个NVS记录写入，成功后才切换控制页。

返回遥控时重新读取已应用快照。未应用的草稿不会影响控制数据。原配置与快照都是值拷贝，修改草稿不会修改已应用记录。

删除需要第二次O确认；切换槽位、动作或返回取消确认。删除当前默认槽位时，默认模式恢复到标准NRC1且保持锁定，不再使用已删除槽位；删除其他槽位不改变默认选择。

如果需要恢复原有标准接收端，在设置菜单选择「默认控制模式 → 标准NRC1协议」，O确认。标准协议仍使用原NRC1解锁、回传确认与独立接收端失联保护，不能把任意硬件ACK当作动作完成。

## 设置菜单

- 射频参数：频道、速率、功率、地址长度；B切到发送地址、接收地址。
- 通信数据：CRC、自动应答、动态长度、接收长度；B查看发送长度/重试/间隔、内置通信预设和收到的数据。
- 发送内容：先选数据来源（手动常量/遥控通道），再查看或编辑字节；B进入字节映射。自动来源的采样字节只读，来源本身可修改。
- 我的预设：保存、应用、删除。
- 摇杆与映射：前后轴、转向轴、方向反转；B进入字节映射。
- 默认控制模式：标准NRC1或当前自定义协议。

设置页面的O统一用于确认/应用，不会启动发送。进入、退出设置及应用配置均保持停止；只有遥控页O可以开始发送。A的停止优先于同时按下的O。

发送中拒绝串口 `@...` 修改命令，并丢弃整个命令行，防止HEX字母被当作按键命令。发送中也拒绝完整截图请求，避免大块USB传输暂停控制。

## 摇杆与逐字节协议

前后只能选择左/右摇杆纵轴，转向只能选择左/右摇杆横轴，可单独反转。默认四驱车左摇杆前后、右摇杆转向；无人机右摇杆前后/横滚，另一横轴负责偏航。标准NRC1自动应用方向设置，接收端字段不变。

自定义协议有32个字节映射，只有配置发送长度（1～32）内的字节发送。接收端需要采用相同顺序和编码。

|来源|编码|
|---|---|
|CONST|对应手动常量字节，可作为包头、命令和固定值|
|LX/LY/RX/RY/KNOB L/KNOB R S8|物理轴-100～100，有符号8位补码|
|上述轴 +100|无符号0～200，中位100|
|上述轴 U8|`(clamp(axis,-100,100)+100)*255/200`，0～255，中位127|
|FORWARD S8 / TURN S8|按前后/转向及反转设置得到的逻辑轴；正数表示前进/右转|
|FORWARD/TURN +100、U8|逻辑轴采用同样偏移或比例编码|
|KEY 0-7 / KEY 8-15 / KEY 16-17|18按键位图的低、中、高字节，见[控制协议](CONTROL_PROTOCOL.md)|
|GYRO X / GYRO Y|当前角度采样，有符号一个字节|
|SEQ LOW / SEQ HIGH|发送计数的低/高字节，小端16位，重新进入控制页从零开始|

原有物理轴来源不会被悄悄改为逻辑方向；需要前后/转向映射时选择FORWARD/TURN。默认前9个字节是六个物理S8轴和三个按键字节。

例如6字节协议：BYTE0=CONST(0xAA)、BYTE1=FORWARD U8、BYTE2=TURN S8、BYTE3=KEY 0-7、BYTE4=SEQ LOW、BYTE5=SEQ HIGH。接收端将p[1]当无符号数，将p[2]转为int8_t，序号为`p[4] | (uint16_t(p[5]) << 8)`。

硬件CRC支持关闭/8/16位；编辑器不实现任意厂商应用层CRC、加密或跳频。双方需匹配参数和数据语义，见[NRF设置](NRF_SETTINGS.md)与[标准控制](NRF_CONTROL.md)。

## 存储与验证

每个车型独立NVS命名空间；槽位保存完整Profile，selected记录同时包含版本、标准/自定义模式、槽位标识和已应用快照。正常关机重启恢复，擦除NVS会清空。Flash写入失败不显示应用成功。

主机测试：`tools/test_nrf_ui_policy.cpp`验证短按/长按B、组合键取消切页、计时环绕、配置锁定，以及498个20ms已启用NRC1帧在显示切换时持续被接收、保持启用且不触发失联。`tools/test_nrf_custom.cpp`验证映射和旧版槽位迁移。

COM11实机回归：`tools/check_nrf_safety_ui.py`针对当前预设1与STM32四字节回显板，验证发送中拒绝配置/截图/串口修改、停止、草稿隔离、默认预设重启恢复和设置返回。只使用空槽位测试删除，完成后恢复预设1默认；不机械操控实体按键，不执行飞控/电机动作。
