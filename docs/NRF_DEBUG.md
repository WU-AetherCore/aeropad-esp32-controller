# NRF 调试

入口：主菜单 → NRF 遥控 → NRF 调试 → O 键进入。B 切换四个页面（统计、参数、数据、通信预设），X 返回 NRF 菜单。界面每100ms刷新，左摇杆在参数页参与方向选择。

## 状态与统计

显示本机模块是否通过 SPI 检测、测试启停、发送次数、收到硬件 ACK 次数、成功率、有效接收及异常包数量。O 启停周期测试，A 清零统计；默认停止发送。

模块已检测不代表对端在线。成功率为 ACK / 发送次数，未发送时显示 --。ACK 只证明无线链路收到应答，不代表对端程序执行了控制命令。强信号检测来自 RPD，表示当前频道检测到强于约 -64dBm 的能量，不是 RSSI、距离或对端在线判断。

## 射频参数

上下选择、左右调整：频道0～83（2400+频道 MHz）、1Mbps / 2Mbps / 250kbps、四档功率、角色0/1、100/200/500/1000ms发送间隔。参数变化会停止测试，请确认后按 O 重新启动。不支持250kbps的芯片自动回退1Mbps。

NDG1预设默认频道76、1Mbps、最低功率、角色0、200ms。角色0接收ADBG0、发送ADBG1；角色1相反。对端必须采用相同频道、速率、5字节地址、固定32字节负载、16位硬件CRC和自动应答。

参数只用于本次调试，不保存到掉电配置；退出恢复原有模块参数和地址，清空调试队列。

## NDG1数据页和测试协议

显示本机与最近接收的左右摇杆数据、接收序号及距最近接收时间。旧接收值保留供诊断，不能当作当前在线证据。旋钮、18个按钮也在测试包中传输。

|字节|内容|
|---|---|
|0～3|ASCII NDG1，专用测试标识|
|4～7|32位小端序号，从0开始|
|8～11|32位小端发送端运行毫秒|
|12～17|六个有符号8位轴：LX、LY、RX、RY、KL、KR，-100～100|
|18～20|18位按键掩码，小端，与控制协议按键位定义一致|
|21～29|保留，必须为0|
|30～31|前30字节 CRC-16/CCITT-FALSE，小端|

本协议是诊断协议，不是无人机或四驱车运动协议。模块硬件ACK统计与软件完整包CRC验证是两项不同的指标。

## 对端联调

[NRF 调试对端示例](../examples/NRF-Diagnostic-Peer/README.md) 可编译烧录到另一块 ESP32-S3，验证后回传同一测试包。仅有遥控器时可以验证本机检测、参数、刷新与没有ACK时的统计；无法证明双向无线传输。无人机与四驱车控制参见 [NRC1通用接收端](NRF_CONTROL.md)。

实现依据：[RF24 官方 API](https://rf24.readthedocs.io/en/latest/classRF24.html)。

## 本次验证（2026-10-07）

遥控器编译并通过 COM11 烧录、哈希核对和复位启动。实机检测到模块；200ms周期测试发送8包、ACK为0（没有独立对端）；启停、频道76/77、速率、功率、角色、间隔修改、三页切换和退出重入通过。检查 SPI 提交帧截图；标题和退出提示完整，无重叠。主机测试验证32字节布局、18位按钮、负数轴、序号、每字节损坏校验及保留位拒绝。独立对端工程编译通过，尚未烧录与双向无线联调。

## 江协参考程序预设

B切页到“通信预设”（第4页），上下选择“江协程序 · 4字节”，O应用。应用时停止发送并清空统计，选择掉电保存；重新进入默认仍停止。预设配置CH2、2Mbps、5字节地址11 22 33 44 55、8位CRC、自动应答和固定4字节数据。发送四个连续递增字节；接收任何4字节原始包，不按NDG1协议验证或误解为摇杆轴。

B返回统计页后O启停，A清零，X停止返回。数据页显示四字节HEX和距最近接收的时间。参考地址在此固定；需要自定义地址或内容请使用“NRF设置”。选回“NDG1专用测试”后恢复原来的32字节诊断协议。

按键现在在各页持续采样，12ms非阻塞消抖，避免切页后没有记录松手。NDG1及原始测试均异步等待射频完成，先恢复RX再绘图；超时120ms取消当前发送。

本次新增江协预设已与ST-Link连接的STM32F103完成无线往返；TX29/ACK29/RX26/BAD0，抓屏和切页期间主循环处理会影响接收统计。27次最大重发配置下的串口切页测试通过。

界面交互统一：只读数据白色，可调项选中时青色底色高亮；江协预设地址是只读项，上下会跳过它。发送状态及发送计数运行中绿色、停止白色。发送中O在所有页面优先停止，停止后需稳定松手再启动，不会因接点抖动重新启发。各页切换时重置选中项。

按用户最新要求，取消灰色文字与边框，恢复白色；选中高亮、发送绿色和停止优先逻辑保留。
