# 热点网页稳定性修复

## 已定位的问题

设备崩溃记录的 CRC 校验有效，记录内固件 ELF 哈希前缀 `82a00bd236ccdd26` 与修复前本地固件一致。出错任务是 `wifi_portal`；堆栈经过 `WebServer::_parseRequest`、`Stream::readStringUntil`、`Stream::timedRead`，最终在 `task_wdt_isr` 触发看门狗中止。这是网络任务等待不完整 HTTP 请求时持续忙等造成的 CPU0 空闲任务饥饿。没有通过关闭或延长看门狗来绕过它。

## 修复方式

- 在 PSRAM 中分段收集完整 HTTP 头和请求体，再调用原有 WebServer 的路由与参数解析。接收循环每轮最多处理 1536 字节，并交还任务调度。
- 请求头最多 4096 字节、请求体最多 24576 字节；拒绝重复/非法 Content-Length、超限报文及本应用不使用的分块上传和 multipart 请求。
- 接收空闲超过 1 秒，或整个请求超过 3 秒时关闭连接；不让手机的残缺请求占住任务。
- 响应发送采用非阻塞分段发送并主动让出 CPU，整个响应预算 1 秒。断开、慢读或 TCP 窗口阻塞的客户端不会阻塞下一次无线模式退出。
- 热点 DNS 使用固定大小缓冲区并校验头、域名标签和数据边界。支持带 EDNS 的普通查询；IPv6 查询返回无 IPv6 记录，让客户端使用 IPv4；异常报文直接丢弃。
- 网页设备状态增加最低可用内存、网页任务剩余栈、请求/超时/异常报文计数、最长处理耗时和复位原因码，便于继续定位手机或网络条件相关问题。

原有中文名称、预设参数与 WiFi 配置存储保持兼容。网页仍不发送车辆运动指令。处理器正常运行在 240 MHz，保留系统看门狗和蓝牙/NRF无线功能隔离。

## 验证

已通过边界单元测试：碎片 HTTP 头、超长/重复长度、分块数据、DNS 截断及 2000 组随机报文。固件已在 COM11 编译烧录并验证 Flash 哈希。手机连接热点网页后，用户反馈暂未再重启；短时现场观察期间串口未记录新的看门狗崩溃。持续并发、慢速客户端和复杂网络条件的板上压力测试尚未全部覆盖。
