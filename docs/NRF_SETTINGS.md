# NRF 设置与原始数据调试

入口：主菜单 → NRF遥控 → NRF设置。此功能单独配置射频，不覆盖无人机、四驱车或 NDG1 调试的参数。退出停止发送并恢复原来的射频配置；保存的是本界面的设置，重进或掉电重启后恢复，发送始终默认停止。

## 操作

- B：循环切换9页；X：停止并返回。
- 设置页：左摇杆或方向键上下选择，左右调整。地址和内容以 BYTE 0 起始，逐字节十六进制编辑；32字节内容自动分页。
- O：启动/停止周期发送；在通信预设页为应用预设，应用后停止发送。
- A：统计页清零计数；发送内容页切换手动数据或遥控通道数据。
- 修改800ms后自动保存到NVS；离开立即保存。保存中/已保存显示于设置页。预设会覆盖当前配置和手动数据。
- 统计页左右切换HEX、TEXT、BIN预览。统计页预览前8字节；接收数据页可上下选择每4字节一组，覆盖全部32字节，支持HEX、TEXT、BIN。TEXT只显示可打印ASCII（其他显示点），完整包通过USB串口日志输出。

## 可调参数

频道0～83（2400+频道 MHz）、速率1Mbps/2Mbps/250kbps、功率4级、地址长度3～5字节；硬件CRC关闭/8位/16位、自动应答、动态长度、固定收发长度各1～32字节；重传间隔250～4000us、次数0～15、发送间隔20/50/100/200/250/500/1000/1500/2000ms。

自动应答需要CRC，开启应答时不会允许关闭CRC。不支持250kbps的旧模块会回退1Mbps。重发较多、间隔较长时一次失败发送可能持续约64ms（硬件异步执行，不阻塞按键轮询），设定20ms并不代表实际达到50Hz。发送成功在关闭应答时只表示本机发出，不证明对端接收到。

## 江协参考程序预设

参考用户提供的《NRF24L01-V1.0/01-NRF24L01两个模块互相通信》，其文件头标注原作者江协科技，创建时间2025-06-09。本项目仅参考寄存器参数与收发流程，以RF24独立实现，未复制其STM32驱动源码。

|参数|设置|
|---|---|
|频道|2，2402MHz|
|速率|2Mbps|
|地址|TX/RX均为11 22 33 44 55，BYTE 0最先写入，不倒序|
|地址长度|5字节|
|固定收发长度|4字节|
|CRC|8位|
|自动应答|开启|
|重发|250us间隔、3次|
|手动数据|00 01 02 03|

本机默认最小发射功率，与参考程序0dBm不同，功率无需双方相同，可以自行调节。参考STM32程序按键触发发送，本机O开启周期发送，收到它的4字节即显示，不需要NDG1或NRC1包头。收发地址相同时双方同时连续发送可能碰撞，调试先让一方接收。

其他预设：通用32字节（CH76、1Mbps、16位CRC、参考地址）；原版遥控地址（发送ASCII 00000，接收ASCII 00001，CH76、1Mbps、32字节、16位CRC）。参考地址预设与原版ASCII地址完全不同。

## 自定义协议与串口注入

手动模式逐字节发送所设数据，没有附加头、序号或软件CRC。固定长度模式发送内容不足时按保存的32字节数组截断；串口注入会清零尾部并调整发送长度。

在本界面，USB串口发送 `@41 54\n`（结尾是真实换行）设为两字节AT。只接受1～32字节完整HEX，错误输入不修改配置。注入不自动启动发送，需O确认。固定长度通信须同时将对端RX长度设为2；本机RX长度独立配置。动态长度模式双方都需开启动态长度。

遥控通道模式：建议发送长度至少9字节；长度不足会截断后面的数据。

|偏移|意义|
|---|---|
|0～3|LX、LY、RX、RY；有符号8位-100～100，负数二进制补码|
|4～5|左、右旋钮；同上|
|6～8|18位按钮位图，低字节先发；定义见CONTROL_PROTOCOL.md中的ControlPacket按钮表|
|9～31|0|

这是新的原始采样布局，和NRC1/NDG1都不同；接收端需要按本表实现解析。不会因为使用同款NRF芯片就知道对方的电机/灯/飞控指令。未知协议设备应先只接收、查看数据，并取得它的地址和协议资料再发送。

## 兼容性边界

NRF24L01不是蓝牙，没有按名称搜索、标准配对或万能控制协议。必须匹配频道、速率、地址及其长度、CRC、固定/动态包格式；发送地址对应对端接收地址，接收地址对应对端发送地址。数据含义仍由对方程序决定。此工具适配配置已知的NRF24L01/兼容设备，不保证任意2.4GHz设备或加密/跳频私有协议可直接控制。

RF24参数依据：[官方类文档](https://rf24.readthedocs.io/en/v1.4.8/classRF24.html)。RPD不是精确RSSI，普通ACK不是执行结果。本次单板验证只能证明界面、参数与持久化及发送流程，需另一台设备才能完成无线互通验证。

## 按键与分区修复

NRF各页每轮采样全部8个功能键，12ms非阻塞消抖；切页不再漏掉松手，长按只触发一次。GPIO扩展芯片一次读取所有输入，减少I2C往返。发送使用异步状态，优先处理TX完成、恢复RX，再采样和绘图，避免错过STM32快速回传。参数变化、停止、清零、退出会取消正在发送的包；输入处理不等待最大重发次数。

统计页按发送、接收和最近数据分框，参数页每项有边框，白色说明单独置于底部操作区。实机按键逻辑用模拟采样序列验证，连续操作与通信用串口控制接口验证；这些测试不能替代所有实体按键接触状态的检查。

2026-10-07最终版实机验证：CH3无对端、4ms重发间隔、15次重发、20ms发送间隔下，27次串口切页全部正确响应，最长指令往返94ms（含测试脚本35ms等待）。恢复CH2后原始数据应答及回传正常。原NRF调试新增江协预设测试最终TX29/ACK29/RX26/BAD0，捕获统计帧时TX15/ACK15/RX15；抓屏会暂停主循环，不将截图过程的统计当作无损链路保证。物理按键的消抖路径由抖动、连续短按、切页释放、长按、同时按键与计时回绕采样测试覆盖。

## 发送状态、选择与停止（2026-10-07）

选中的可调项使用青色高亮与底色，未选中可调项保持白色；接收统计、接收内容等只读项使用白色，不给选择高亮。自动遥控数据源的发送内容为实时采样，只读白色，左右不会修改隐藏的手动数据。发送中状态和发送计数绿色，停止时白色；操作说明始终白色。

发送中O在任意页面都是停止，包含通信预设页。停发优先于应用预设；稳定松手40ms后才允许下一次启动，防止接点反复抖动导致停止后重启。启动需稳定按下12ms，停止使用首次观察到的按下。停止立即取消在途任务；接收仍开启，因此对端最后的回传可能继续增长RX计数，TX计数应保持不变。

原始串口日志依然默认开启，缓冲不足时跳过该日志包，不阻塞等待USB。V切换日志开关；无线接收统计不因跳过日志而丢失，终端日志不作为无损抓包工具。

按用户最新要求，取消灰色文字与边框，恢复白色；选中高亮、发送绿色和停止优先逻辑保留。
