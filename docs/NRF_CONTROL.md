# NRF 无人机与四驱车控制

入口：主菜单 → NRF 遥控 → 无人机 / 四驱车。遥控器固件同时包含两种控制模式；接收板按用途分别编译 `drone` 或 `car`。两者使用自定义 NRC1 协议，不能直接兼容任意商业 NRF 接收器。

## 操作与界面

- B：切换实时控制、链路回传、参数设置三个页面。
- 长按 O 至少1秒：在接收端在线、摇杆回中及无人机油门低的条件下启用控制。没有接收端回传时无法启用；请求后100ms仍未得到接收端解锁确认，会重新锁定。
- A：立即锁定并发送停止命令。再次解锁需松开 O 后重新长按。
- X：发送三次停止命令后返回 NRF 菜单；接收端仍有独立250ms失联保护。
- 参数页：锁定时上下选项、左右修改，也可用左摇杆。控制已启用时参数锁定，摇杆继续作为遥控输入。

接收端在线状态必须收到完整校验通过、模式正确且序号及时的回传。只有硬件 ACK 不会显示在线。回传显示接收端自身的锁定状态和累计有效收包数；旧回传保留作诊断，黄色未连接表示已过期。

射频参数为频道0～83、1Mbps/2Mbps/250kbps、四档功率，初始频道76、1Mbps、最低功率。不支持250kbps时回退1Mbps。四驱车默认限速25%；无人机默认姿态幅度100%，可调25/50/75/100%。两种模式参数各自自动保存到 NVS，重启后恢复；解锁状态永不保存。退出恢复遥控器原有射频配置。

## 控件映射

|控件|无人机|四驱车|
|---|---|---|
|左摇杆 X|偏航|-|
|左摇杆 Y|-|前进/后退，上推前进|
|右摇杆 X|横滚|左右转向、差速混控|
|右摇杆 Y|俯仰，上推为正|-|
|左旋钮|油门0～100%，采样输出+100为最低、-100为最高|保留原始通道|
|右旋钮|SBUS辅助CH6|保留原始通道|
|其他按钮/拨杆|18位原始掩码；部分映射到SBUS辅助通道|全部原始掩码，接收程序可扩展灯光等|

无人机解锁要求左旋钮油门≤5%、偏航/横滚/俯仰原始值在±10以内。四驱车要求前后与转向原始值在±10以内。油门行显示“采样 / 输出”：锁定时输出为0，但仍显示旋钮当前位置，方便调整到≤5%。旋钮最低方向请先根据屏幕确认；不正确时先做控件校准。

## 通用接收端

完整工程：[NRF-Control-Receiver](../examples/NRF-Control-Receiver/README.md)。这是另一块 ESP32-S3 的程序，不要烧录到遥控器 COM11。

默认 NRF 接线：CE43、CSN42、SCK12、MISO13、MOSI11。模块使用3.3V电源并共地，稳定供电；PA/LNA模块需要按模块规格供电。接收端的频道、速率、地址和ACK负载设置必须与遥控器一致。

|模式|接收地址（5字节ASCII）|输出|
|---|---|---|
|无人机|NDRN1|GPIO17，反相SBUS，100000波特率、8E2，14ms周期|
|四驱车|NCAR1|两路方向/PWM接口，可用于TB6612类差速驱动|

### 无人机飞控接入

接收板 GPIO17 → 兼容反相SBUS的飞控接收输入，连接共同地线。在飞控中选择SBUS接收协议并确认以下通道：CH1横滚、CH2俯仰、CH3油门、CH4偏航、CH5解锁开关、CH6右旋钮。CH7～CH16依次是A、B、X、O、左上、左下、右上、右下、左板载、右板载按钮。A/X同时用于本地急停/退出，触发后接收端锁定并清零辅助通道；不能将这两个键当作飞行中的普通辅助开关。

本程序是接收器，不包含飞控姿态闭环或四电机混控。请在飞控接收机页核对方向和端点，按飞控说明配置CH5解锁及失联动作。接收端锁定/失联时CH3及CH5降到最低；失联同时置SBUS丢帧和failsafe位。初次通道、解锁和失联验证应拆除螺旋桨。

### 四驱车接入

两左轮共享左驱动、两右轮共享右驱动，得到前后、转弯和原地旋转。`ReceiverConfig.h` 集中配置方向引脚、PWM引脚、待机引脚与电机反向：左IN1/IN2=5/6、右IN1/IN2=7/8、左PWM9、右PWM10、STBY4。PWM为20kHz、8位，占空比按百分比映射；转向混控按最大幅值统一缩放，保持转弯比例，再乘速度限制。

`MOTOR_OUTPUT_ENABLED` 默认false，因为通用板没有已确定的电机接线。核对实际驱动和引脚后改为true再编译。锁定和失联时PWM归零、STBY拉低；改变方向时先关闭驱动再切换。不能将电机直接接ESP32 GPIO。

## NRC1 控制帧

固定32字节，20ms发送，所有多字节字段小端。不是原BLE20字节帧，也不是NDG1诊断帧。

|字节|字段|
|---|---|
|0～3|ASCII NRC1|
|4～5|16位序号，自动环绕|
|6|模式：1无人机、2四驱车|
|7|1控制请求，2锁定/停止；其他值拒绝|
|8～13|有符号8位 LX、LY、RX、RY、KL、KR，-100～100|
|14～15|有符号8位陀螺仪AX、AY，-100～100|
|16～18|18位按键掩码，位序同[BLE控制协议](CONTROL_PROTOCOL.md)|
|19～22|发送端运行毫秒，32位|
|23|姿态幅度/限速百分比25～100|
|24～27|32位本次进入页面的随机会话标识|
|28～29|保留0|
|30～31|前30字节CRC-16/CCITT-FALSE，初值FFFF、多项式1021|

接收端拒绝损坏、越界、模式不匹配、保留位非法帧。重复/旧序号不刷新250ms看门狗；有效停止帧即使重复也锁定。新会话、接收板重启或失联后，需要先收到锁定帧再在中立条件下接受控制请求，避免恢复链路时自动继续运动。CRC是错误检测，不是无线身份认证。

## NRF1 回传帧

通过自动ACK负载回传，固定32字节，通常比当前控制帧落后一个周期。

|字节|字段|
|---|---|
|0～3|ASCII NRF1|
|4～5|最近接受的控制序号|
|6|接收端模式|
|7|bit0已解锁、bit1失联保护、bit2接收协议就绪|
|8～11|累计接受帧数|
|12～15|累计拒绝帧数|
|16～17|电池毫伏，FFFF表示未配置测量，不伪造电量|
|18～25|接收端当前有效的六轴和两陀螺仪通道，锁定时归零（左旋钮+100）|
|26|当前姿态幅度/限速|
|27～29|会话标识的低24位，用于排除旧回传|
|30～31|前30字节CRC，算法同控制帧|

回传确认的是接收程序状态。它不证明飞控已解锁、电机已旋转或车辆已移动。通用接收端尚未连接实体飞控/电机，电压ADC未配置，因此不会显示虚构电压。

## 验证记录（2026-10-07）

遥控器编译与COM11烧录通过；无人机/四驱车两模式六页面通过串口读取SPI实际提交帧检查，左右摇杆框均101×101。验证无对端时保持锁定、参数调整、急停/退出/重入，以及修改频道后复位恢复NVS；测试后恢复频道76。NRF调试页亦复测通过。主机测试覆盖CRC损坏、越界/保留位、模式拒绝、解锁条件、重复包不喂狗、重复停止、新会话锁定、250ms超时与计时环绕、差速混控上限、回传及16通道SBUS端点/中立/failsafe。通用接收端car/drone两环境编译通过。

没有独立接收板连接，因此无线ACK回传、接收板实体SBUS、电机转动和实际飞控动作尚未完成硬件联调，不以主机测试代替实测。遥控器端锁定条件与失联后的显示可实测；接收端解锁回传需后续接收板验证。
