# 连接与数据排查

|现象|先检查什么|原因与处理|
|---|---|---|
|蓝牙已连接但电机不动|是否进入“模块控制”，接收端是否在解析|连接只代表链路；桥接示例不驱动电机，控制示例须适配 `applyOutputs()`|
|电脑能配对手柄，串口却没有v1帧|选的是HID还是模块控制|HID不是BLE-UART，不走四种自定义发送格式|
|串口乱码|线上格式与助手显示模式|原始二进制按HEX看；JSON/文本/HEX文本按文本看|
|发送AT却屏幕显示41 54|回显模式|HEX显示ASCII字节编码，文本模式才显示AT；对方还要实际回传这些字节|
|文本接收只有半行|是否按LF拼接|一次BLE写/通知、一次UART读取不等于完整帧|
|偶发解析错误|CRC、溢出、格式切换|限长、丢弃坏包、重新同步；切换格式先停输出并清接收缓冲|
|改波特率仍乱码|模块→目标板电气UART两端|8N1、波特率和3.3V逻辑要一致；USB CDC/BLE没有同一个电气UART波特率|
|对方UART设置“不支持”|是否有扩展特征0004|模块名WUFUDONG不是芯片型号；无兼容扩展则用该模块自己的文档配置|
|短时停顿后突然执行旧命令|队列、重复序号和有效帧看门狗|不得用任意字节刷新控制有效时间；超时停止并清半帧|
|CLion找不到upload/firmware|运行配置类型|这两个是构建目标；见 [构建说明](BUILD_AND_FLASH.md)|
|nRF识别到了却不能遥控车|设备控制页面是否实现|使用NRC1接收端，核对频道/速率/模式地址、回传、解锁条件和电机输出开关；见[NRF控制](NRF_CONTROL.md)|

## 最小检查顺序

1. 目标端从日志确认每帧序号、轴、按键、neutral，不连接执行器先检查。
2. 遥控器选择二进制/50ms，目标UART使用115200/8N1，确认RX/TX交叉与共地。
3. 按A查看 `buttons & 1`，推动左摇杆确认LY、右摇杆确认RX方向。
4. 正常静止包 `neutral=0` 不是退出释放包。退出释放包 `neutral=1`，接收端应停止。
5. 关闭遥控器或断开链路，确认目标在自己的失联时限内停止；CRC坏包不应延长有效控制时间。
6. 确认软件控制意图后再实现设备驱动；映射、限幅、方向和停止状态由目标硬件决定。

TX计数仅表示逻辑帧提交到BLE写入，RX是通知字节数，ERR是写入错误数，不是车辆执行成功确认。项目没有通用的执行ACK协议；需要确认设备动作时，应由接收端另行定义并回传状态。
